# 维护者指南（换数据 / 重训模型 / 发布）

> 本目录（training/）**不属于网站运行时**。网站跑起来完全不需要它，
> 只有"要给模型换新数据"时才用。所有路径以 `<项目根目录>` 表示，不写具体盘符与用户名。

## 1. 环境准备（一次性，独立 venv）

```bash
cd "<项目根目录>"
python -m venv .venv/training
.venv/training/Scripts/python -m pip install -U pip          # PowerShell: .venv\training\Scripts\python.exe
.venv/training/Scripts/pip install -r training/requirements.txt
```

之后所有训练命令都用 `.venv/training/Scripts/python`。
**为什么隔离**：ultralytics 会拉 torch（2 GB+），对 numpy/opencv 版本挑剔；
而站点服务 `server/serve.py` 零依赖。混在一起只会让"起不来"的原因变模糊。

没有本地 GPU 也可以用 Google Colab 免费版：把 `datasets/` 上传，跑同样的三个脚本，
把产出的 `best.onnx` + `manifest.json` 下载回来放进 `app/models/`。

## 2. 三步流水线

| 步骤 | 命令 | 输入 → 输出 |
|---|---|---|
| ① 整理数据集 | `python training/prepare_dataset.py --out datasets/slbg_v1` | `data/captures/` → `datasets/slbg_v1/` + `data.yaml` + `classes.json` |
| ② 训练 | `python training/train_yolo.py --data datasets/slbg_v1/data.yaml --epochs 100` | → `training/runs/<name>/weights/best.pt` |
| ③ 导出部署 | `python training/export_onnx.py --weights <best.pt> --classes datasets/slbg_v1/classes.json --imgsz 320` | → `app/models/best.onnx` + `manifest.json` |

`prepare_dataset.py` 会**按拍摄者划分验证集**（同一个人不会既在训练集又在验证集），避免指标虚高。
`export_onnx.py` 会自动写出 `app/models/manifest.json`，其中 `classes` 是前端"能玩什么"的唯一真相。

## 3. 换数据集 / 加新类别

- **替换现有数据**：把新图片与标签放进 `datasets/<名字>/{images,labels}`，重跑 ①→②→③ 即可。
- **新增类别**：保证 `classes.json` 里每个类的 `signId` 与前端词库 `app/js/data/signs.js` 的 `id` **一致**，
  并把该词条的 `yoloClass` 填上模型里的类名。两边对不上时，前端会自动当"模型不认识"处理（不会乱出题）。
- **未来替换 gesture_6**：直接替换 `datasets/gesture_number_6/` 内容后重跑流水线，前端无需改代码。

## 4. manifest.json 要点

```jsonc
{
  "classes": [ { "id": 0, "name": "gesture_number_6", "signId": "number-6", "zh": "数字 6" } ],
  "thresholds": { "score": 0.35, "iou": 0.45, "holdMs": 1200 }
}
```

- `signId` 必须与词库 id 一致；改错会导致该类别无法进入题池（这是安全行为，不是 bug）。
- 阈值可在前端「我的 → 设置」里被玩家覆盖（保持时长），这里给的是默认值。

## 5. 发布到 GitHub Pages

```bash
git add -A && git commit -m "update model: <说明>"
git push origin master
```

Pages 会自动重新部署（约 1–2 分钟）。首次配置路径：
`Settings → Pages → Build and deployment → Source: Deploy from a branch → master / (root)`。

注意：`app/models/best.onnx` 约 12 MB，属于仓库内容，会随 Pages 一起发布；
仓库体积变大时可考虑 Git LFS，但当前规模不需要。

## 6. 发布前自查清单

- [ ] `python server/serve.py` 起服务，`node tools/e2e_smoke.mjs` 全绿（含"题池只含模型认识的词"断言）；
- [ ] 全仓搜索无真实用户名、绝对盘符路径：`grep -rn "C:\\\\Users" .` 应为空；
- [ ] `datasets/` 内所有真人素材都有授权记录；
- [ ] `app/models/manifest.json` 的类别数与训练结果一致；
- [ ] README 与 docs 里的路径都是相对路径或 `<项目根目录>`。

## 7. 备份与迁移

- 玩家进度在玩家自己浏览器里，维护者看不到也拿不到——这是设计选择，请在文档里提醒玩家定期导出备份。
- 仓库自带的一切（代码、数据集、模型）由 Git 保证。训练中间产物（`training/runs/`）不入库。
