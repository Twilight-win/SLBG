# 架构说明

## 1. 总体分层

```
┌──────────────────────────────────────────────────────┐
│ 前端（静态，GitHub Pages / 本地 serve.py）             │
│   index.html + app/                                   │
│   · 推理：onnxruntime-web 跑 YOLOv8n（best.onnx）      │
│   · 关键点：MediaPipe HandLandmarker（21 点）          │
│   · 端侧训练：TinyMLP（63→64→32→N，浏览器内）          │
│   · 存储：localStorage（进度/模型）+ IndexedDB（图片） │
├──────────────────────────────────────────────────────┤
│ 数据通道（仓库即社区）                                 │
│   浏览器采集 → 导出 ZIP（words/samples/images）        │
│   → fork + Pull Request → datasets/                    │
├──────────────────────────────────────────────────────┤
│ 训练环境（独立 venv，与前端零耦合）                    │
│   prepare_dataset → train_yolo(yolov8) → export_onnx  │
│   产物：app/models/best.onnx + manifest.json          │
└──────────────────────────────────────────────────────┘
```

**为什么没有后端**：免费 + 长期可维护 + 隐私。静态托管最稳，推理放浏览器，
训练放本地/Colab，两边通过"仓库里的文件"通信，天然隔离。

## 2. 目录规范

| 目录 | 放什么 | 不放什么 |
|---|---|---|
| `app/` | 前端运行时（css/js/models/vendor/assets） | 训练代码、数据集、日志 |
| `datasets/` | 提交进仓库的公开数据集 | 代码、模型、临时文件 |
| `data/captures/` | 本地采集落盘（**不入库**） | 任何需要提交的东西 |
| `training/` | 训练脚本与 venv | 前端代码 |
| `server/` | 本地静态服务（零依赖） | 业务逻辑 |
| `tools/` | 测试与调试脚本 | 运行时依赖 |
| `docs/` | 文档 | 代码 |

铁律：
- 模型产物只能通过 `training/export_onnx.py` 写入 `app/models/`，不手工拷贝；
- 文档与注释里的路径一律写 `<项目根目录>`，禁止出现具体用户名/盘符；
- 前端不得假设自己在某个固定子路径下（模型与 vendor 路径都由 `import.meta.url` 推导）。

## 3. 关键模块

| 文件 | 职责 |
|---|---|
| `app/js/engine/yolo.js` | 加载 manifest → letterbox 预处理 → ORT Web 推理 → 输出检测框 |
| `app/js/engine/decoder.js` | 纯函数解码 `[1,5,2100]` → 框 + 分数（可单测） |
| `app/js/engine/landmarks.js` | MediaPipe HandLandmarker，输出 21 点 → 63 维归一化特征 |
| `app/js/engine/capability.js` | **能力中心**：决定"能玩什么题"+ 双模型融合判定 + 保持判定 |
| `app/js/engine/tinymlp.js` | 浏览器内小网络：标准化、训练、留一评估、持久化、导出/导入 |
| `app/js/data/signs.js` | 词库 + 自建词条索引（每个词条显式声明 `yoloClass`） |
| `app/js/data/idb.js` / `zip.js` | 示例图存储 / 零依赖 ZIP 打包 |
| `app/js/core/store.js` | 进度存储、SM-2 复习队列、备份导出/导入 |
| `app/js/games/feedback.js` | 答对/答错的反馈与 tips 卡片 |

## 4. 能力中心：为什么不会再说"请比出八"

旧版 bug：词库 17 条，模型只有 1 类，游戏照着词库随机出题 → 永远判不过。

现在的约束链：
1. `manifest.json` 声明模型认识的类别（含 `signId`）；
2. 词条用 `yoloClass` 显式声明对应关系，`null` = 模型不认识；
3. `capability.playable()` = YOLO 认识 ∪ 端侧已训练，AI 判定类游戏只能用它出题；
4. `tools/e2e_smoke.mjs` 有断言守着："题池含六且不含八"。

模型换了新的，只需更新 `manifest.json` + `best.onnx`，前端自动跟着变，不需要改代码。

## 5. 多模态示例（现状与规划）

- **现状**：每词支持多张静态示例图，图带 `step` 序号 + 文字要点，页面上按顺序展示（对应手语字典"先看哪一步"的表达）。
- **已预留**：词条结构里有 `videos: [{ url, poster }]`，当前不渲染；采集页支持短视频后可直接启用，不需要改数据结构。
- **动态词**（谢谢、再见）当前以文字步骤表达，未来接时序模型（21 点序列 + BiGRU 思路已备忘在旧代码里，等数据足够再做）。

## 6. 群组空间（v2 规划，本版不做）

需求：社团内部私有词库，可邀请成员共建。
本版的替代方案：数据包导出 → PR 合入 → 共享同一份模型与词表（公开、可审核）。
真正私有化需要账号体系与后端存储，可用方案：GitHub 组织/分支即空间，或免费 Serverless（如 Cloudflare Workers + KV）。
届时还需约定内容审核规则，防止不良信息——这也是本版刻意不做账号的原因。

## 7. 测试

```bash
python server/serve.py        # 另开一个终端
node tools/e2e_smoke.mjs      # 真浏览器（Edge/Chrome）冒烟，覆盖首页/引擎/游戏/训练营/词工坊
```

覆盖点：页面渲染、真实 ONNX 推理、题池正确性、摄像头舞台挂载、MediaPipe 加载、
记忆/拼图交互、自建词条写入与进入可训练池、控制台无 JS 错误。
